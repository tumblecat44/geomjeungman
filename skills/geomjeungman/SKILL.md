# 검증맨

## 목적과 범위

하나의 화면을 여러 크기에서 열어 텍스트, 이미지, 버튼 같은 요소가 잘리거나 겹치는지 확인한다. 각 크기의 실측값과 스크린샷을 남기고, 확인한 문제의 위치를 표시한다.

한 번에 웹 URL 하나 또는 앱 화면 하나를 검사한다. 화면 전체나 화면 안의 특정 영역을 대상으로 삼을 수 있다. 화면을 준비할 때는 지정된 탭이나 모달을 여는 데 필요한 조작까지만 한다.

## 1. 검사할 화면을 정한다

대상을 따로 지정하지 않으면 현재 작업 디렉터리의 프로젝트를 사용한다. 프로젝트의 실행 안내를 따라 앱이나 웹을 연다. 웹은 URL을, 앱은 이름과 화면을 기록한다. 프로젝트와 요청을 보고도 화면을 하나로 고를 수 없으면 검사할 화면을 묻는다.

이 단계의 결과로 **대상과 화면 상태**를 한 줄로 적는다. 예를 들어 `http://localhost:3000/pricing, 가격표 영역`처럼 적는다.

## 2. 검사할 크기를 정한다

사용자가 지정한 크기가 있으면 그대로 쓴다. 크기가 정해져 있지 않으면 아래 기준을 따른다.

- 웹은 브라우저에서 페이지가 보이는 영역을 바꾼다. 넓은 화면, 좁고 긴 화면, 같은 너비의 낮은 화면을 비교한다. 프로젝트 기준이 없다면 `1440×900`, `390×900`, `390×600` CSS 픽셀을 쓴다.
- 데스크톱 앱은 실제 창을 바꾼다. 기본 창 크기, 기본 높이에서 최소 너비, 최소 창 크기를 비교한다. 앱의 문서나 창 설정에서 최소 크기를 확인한다. 최소 크기를 알 수 없으면 앱이 허용하는 크기를 쓰고 확인한 범위를 적는다.
- 모바일 앱은 시뮬레이터나 테스트 기기에서 앱이 지원하는 크기 중 작고 큰 화면을 고른다. 회전이 검사 범위에 있고 앱이 회전을 지원하면 가로 화면도 포함한다.

이 단계의 결과로 **요청한 크기 목록과 측정 기준**을 적는다. 데스크톱 창 크기와 앱 내용이 보이는 영역의 크기는 따로 기록한다.

## 3. 같은 화면을 크기별로 캡처한다

각 크기에서 같은 화면과 상태를 확인한다. 보고 있는 화면이 맞는지 제목, 모달이나 주요 요소로 확인한 다음 실제 크기를 재고 스크린샷을 저장한다. 화면에 도달하지 못하거나 크기를 잴 수 없으면 해당 항목을 `미검증`으로 남기고 이유를 적는다.

- 웹과 Electron에서는 Agent Browser가 크기를 바꾸고, 실제 크기를 재고, PNG를 저장한다. 성능, 콘솔 오류, 네트워크 로그는 Chrome DevTools MCP에서 확인한다.
- 웹은 `python3 "$SKILL_DIR/scripts/agent_browser.py" --session 검증맨 open URL`로 연다. 세션에 열린 탭이 없으면 촬영 단계에서 URL을 연다.
- Electron은 프로젝트 안내에 따라 로컬 DevTools 포트를 연다. Agent Browser를 연결하고 해당 앱 탭을 선택한다. 앱 창을 조절할 때는 `--electron`을 붙인다. 촬영 명령에서 `--cdp 포트`를 함께 주면 그 주소로 연결한다.
- 다른 데스크톱 앱은 운영체제의 창 제어 도구로 창을 조절하고, 모바일 앱은 시뮬레이터나 기기에서 화면을 연다. 이 절차의 `capture.py`는 웹과 Electron을 지원한다. 그 밖의 앱은 연결된 플랫폼 도구로 측정하고 캡처한다. 도구를 사용할 수 없으면 `미검증`으로 기록한다.

웹과 Electron에서는 화면을 확인하고 `--url`에 기대하는 주소, `--require`에 그 화면을 알아볼 CSS 선택자를 준다. 로그인 화면에도 있는 `main`, `body`, `#root` 같은 표식은 거부한다. 정상적으로 주소가 바뀌는 흐름이라면 검사할 화면의 최종 주소를 지정한다. 한 줄로 온전히 보여야 할 글자가 있으면 화면 영역 안의 요소를 `--text`로 지정한다. 여러 요소를 볼 때는 옵션을 반복한다.

```bash
python3 "$SKILL_DIR/scripts/capture.py" --session 검증맨 --name 가격표-반응형 \
  --url 'http://localhost:3000/pricing' --require '#pricing-table' --text '.purchase-button' \
  1440x900 390x900 390x600
```

`SKILL_DIR`는 이 `SKILL.md`가 있는 폴더다. Agent Browser 명령이 없으면 스크립트가 npm으로 사용자 캐시에 설치한다. 웹용 Chrome을 사용할 수 없는 환경은 `python3 "$SKILL_DIR/scripts/agent_browser.py" install`로 브라우저도 준비한다. 창을 줄일 때 메뉴가 닫히면 버튼을 `--reopen`으로 지정한다. 데이터가 들어온 뒤에 나타나는 요소가 있으면 `--ready`로 지정한다. 스크립트는 각 크기의 기록을 저장하고, 촬영을 마치면 시작 크기를 복원한다.

이 단계의 결과로 **실측값과 원본 스크린샷**을 남긴다. 검증한 화면과 상태를 보고 `가격표-반응형`처럼 검사 이름을 짓는다. 결과는 `.geomjeung/YYYY-MM-DD/<검사-이름>/`에 저장한다. 날짜는 실행 환경의 현지 날짜다. 같은 이름으로 다시 검사하면 `-2`, `-3`을 붙여 이전 결과를 보존한다. 사진이 없는 크기도 `report.json`의 `captures`에 사유와 함께 남는다. 크기가 맞지 않으면 참고 사진에 실측 크기를 붙인다. 촬영 스크립트의 실행 완료는 보고서가 저장됐다는 뜻이다. 요청 크기별 화면 판정은 5단계에서 한다.

## 4. 잘리거나 겹친 곳을 표시한다

정상 촬영된 크기마다 `report.json`의 `layout` 값과 원본 스크린샷을 함께 확인한다. 코드가 페이지 전체의 가로 넘침과 `--text`로 지정한 한 줄 글자의 칸 너비와 내용 너비를 잰다. 표나 캐러셀 안에서만 스크롤되는 경우와 의도한 말줄임은 정상일 수 있다. 숫자에서 나온 신호는 화면과 의도를 보고 판단한다. 사진에서는 텍스트나 버튼의 잘림과 요소가 서로 겹치는 곳을 찾는다. 웹과 Electron에서 원인을 확인할 때는 같은 화면의 요소 위치나 CSS를 근거로 삼는다.

문제가 보이면 이미지 왼쪽 위부터 센 픽셀 좌표로 표시할 영역의 `x,y,너비,높이`를 정한다. 브라우저의 CSS 픽셀을 쓴 경우에는 스크린샷의 실제 픽셀 크기에 맞춰 변환한다. 예시의 숫자는 문제가 보이는 영역으로 바꾼다. 한 이미지에 여러 곳을 표시하려면 `--box`를 반복한다.

```bash
python3 "$SKILL_DIR/scripts/annotate.py" 02-390x900.png --box 278,92,96,42
```

이 단계의 결과로 **문제에 박스를 그린 이미지**를 남긴다. 스크립트는 원본 PNG 옆에 `02-390x900-marked.svg`를 만든다. 원본 PNG는 그대로 보존한다.

관제탑에서 박스별 설명을 볼 수 있도록 `report.json`의 해당 `captures` 항목에 `issues`를 기록한다. 문제 하나당 항목 하나를 쓴다. `box`는 원본 PNG 픽셀 기준 `[x, y, 너비, 높이]`다. `problem`에는 관찰한 현상을, `suggestion`에는 고칠 방법을 한 문장씩 쓴다. 실제 화면에서 확인한 문제만 기록한다.

```json
{
  "box": [278, 92, 96, 42],
  "problem": "좁은 화면에서 구매 버튼의 오른쪽이 잘립니다.",
  "suggestion": "좁은 화면에서는 버튼을 다음 줄로 옮기고, 컨테이너 너비를 넘지 않게 제한하세요."
}
```

이미지 미리보기에 도움이 되는 화면 배경은 보고서 최상위의 `context`에 짧게 적는다. 시안으로 보낼 수 있는 정보만 넣는다.

## 5. 결과를 남긴다

에이전트는 정상 촬영된 각 항목의 `review`에 사진과 숫자를 확인한 결과를 적는다. 깨짐을 못 찾았으면 `status`는 `clear`, 문제를 찾았으면 `issue`, 확인할 근거가 부족하면 `uncertain`이다. `summary`에 이유를 적고, `issue`인 경우 4단계의 `issues`에 확인한 문제를 쓴다. 수치에 넘침이나 측정 누락이 있는데도 화면이 정상이라고 판단하면 `measurement_note`에 이유를 적는다.

```bash
python3 "$SKILL_DIR/scripts/finish.py" "$RESULT_DIR/report.json"
```

스크립트가 크기마다 판정을 하나씩 정해 `report.json`에 기록하고, `findings.md`에 촬영 결과, 측정값, 사진 판정과 사진 링크를 적는다.

촬영 중이거나 사진 검토를 끝내지 못한 기록은 관제탑에서 `미완료`로 보인다. 검사 도중 멈춰 다시 실행하면 새 폴더가 생기고 이전 사진과 판정은 이전 폴더에 남는다.

- **0** · 요청한 화면과 크기를 확인했고 깨짐을 찾지 못했다.
- **1** · 요청한 화면과 크기에서 깨짐을 확인했다.
- **2** · 화면이나 크기가 맞지 않았거나 판정할 근거가 부족했다.

플랫폼 도구로 직접 촬영해 `report.json`이 없는 경우에는 같은 기준으로 `findings.md`를 작성한다. 요청 크기, 실측 크기, 판정 이유와 사진 링크를 기록한다.

## 6. 관제탑에서 결과를 연다

결과를 기록한 뒤 검사 대상 프로젝트의 루트에서 관제탑을 갱신한다. `RESULT_DIR`에는 이번 검사 폴더의 경로를 지정한다.

```bash
python3 "$SKILL_DIR/scripts/dashboard.py" --run "$RESULT_DIR" --open
```

스크립트는 날짜별 검사 기록을 `.geomjeung/index.html`에 모으고 이번 검사를 기본 브라우저에서 연다. 결과의 캡처와 기록을 참조하므로 HTML 파일은 `.geomjeung` 안에 둔다. 브라우저를 열 수 없으면 사용자에게 HTML 파일 경로를 알려준다.

사용자가 이미지 시안 생성을 원하면 프로젝트 루트에서 다음 명령으로 관제탑을 연다. 이미지 생성이 가능한 Codex CLI 로그인이 필요하다. 명령을 종료하면 로컬 생성 기능이 꺼진다.

```bash
python3 "$SKILL_DIR/scripts/dashboard.py" --run "$RESULT_DIR" --serve --open
```

빨간 박스 위에 마우스를 올리거나 키보드로 선택하면 해당 문제와 수정 제안이 보인다. **어떻게 변할지 보기**를 누르면 그 스크린샷의 원본, 화면 배경, 모든 수정 제안으로 생성할 내용을 확인할 수 있다. **이미지 생성**을 누르면 Codex CLI가 시안을 만들고, 주황색 카드로 표시한다. 생성한 이미지는 검사 폴더의 `previews/`에 저장한다. 시안을 보고 수정하기로 했다면 **수정 요청 복사**를 사용할 수 있다.
