# 검증맨

## 목적과 범위

하나의 화면을 여러 크기에서 열어 텍스트, 이미지, 버튼 같은 요소가 잘리거나 겹치는지 확인한다. 각 크기의 실측값과 스크린샷을 남기고, 확인한 문제의 위치를 표시한다.

한 번에 웹 URL 하나 또는 앱 화면 하나를 검사한다. 화면 전체나 화면 안의 특정 영역을 대상으로 삼을 수 있다. 화면을 준비할 때는 지정된 탭이나 모달을 여는 데 필요한 조작까지만 한다.

## 1. 검사할 화면을 정한다

웹은 열 수 있는 URL 하나를 받는다. 데스크톱 앱이나 모바일 앱은 앱 이름과 화면 하나를 받는다. 사용자가 새로 추가한 부분을 확인해 달라고 하면, 같은 화면에서 볼 영역을 기록한다. 요청이나 제공된 주소만으로 화면을 특정할 수 없으면 어떤 화면을 검사할지 묻는다.

이 단계의 결과로 **대상과 화면 상태**를 한 줄로 적는다. 예를 들어 `http://localhost:3000/pricing, 가격표 영역`처럼 적는다.

## 2. 검사할 크기를 정한다

사용자가 지정한 크기가 있으면 그대로 쓴다. 크기가 정해져 있지 않으면 아래 기준을 따른다.

- 웹은 브라우저에서 페이지가 보이는 영역을 바꾼다. 넓은 화면, 좁고 긴 화면, 같은 너비의 낮은 화면을 비교한다. 프로젝트 기준이 없다면 `1440×900`, `390×900`, `390×600` CSS 픽셀을 쓴다.
- 데스크톱 앱은 실제 창을 바꾼다. 기본 창 크기, 기본 높이에서 최소 너비, 최소 창 크기를 비교한다. 앱의 문서나 창 설정에서 최소 크기를 확인한다. 최소 크기를 알 수 없으면 앱이 허용하는 크기를 쓰고 확인한 범위를 적는다.
- 모바일 앱은 시뮬레이터나 테스트 기기에서 앱이 지원하는 크기 중 작고 큰 화면을 고른다. 회전이 검사 범위에 있고 앱이 회전을 지원하면 가로 화면도 포함한다.

이 단계의 결과로 **요청한 크기 목록과 측정 기준**을 적는다. 데스크톱 창 크기와 앱 내용이 보이는 영역의 크기는 따로 기록한다.

## 3. 같은 화면을 크기별로 캡처한다

각 크기에서 같은 화면과 상태를 확인한다. 보고 있는 화면이 맞는지 제목, 모달이나 주요 요소로 확인한 다음 실제 크기를 재고 스크린샷을 저장한다. 화면에 도달하지 못하거나 크기를 잴 수 없으면 해당 항목을 `미검증`으로 남기고 이유를 적는다.

- 웹은 `agent-browser --session 검증맨 open URL`로 연다. 개발 서버가 필요하면 프로젝트의 실행 안내에 따른다.
- Electron 앱은 프로젝트의 안내에 따라 로컬 DevTools 포트를 연다. `agent-browser --session 검증맨 connect 포트`로 연결한 뒤 해당 앱 탭을 선택한다. 실제 창을 조절할 때는 기기나 페이지 영역을 따로 설정하지 않은 세션에서 `--electron`을 쓴다.
- 다른 데스크톱 앱은 운영체제의 창 제어 도구로 창을 조절하고, 모바일 앱은 시뮬레이터나 기기에서 화면을 연다. 이 절차의 `capture.py`는 웹과 Electron을 지원한다. 그 밖의 앱은 연결된 플랫폼 도구로 측정하고 캡처한다. 도구를 사용할 수 없으면 `미검증`으로 기록한다.

웹과 Electron에서는 `snapshot`으로 화면을 확인하고 화면 상태를 식별하는 CSS 선택자를 고른다. 검사 대상 프로젝트의 루트에서 아래 예시의 경로, 세션, 검사 이름, 선택자, 크기를 실제 값으로 바꿔 실행한다. 명령을 처음 실행하는 환경이라면 `agent-browser` CLI를 설치한 뒤 `agent-browser install`로 브라우저를 준비한다.

```bash
python3 "$SKILL_DIR/scripts/capture.py" --session 검증맨 --name 가격표-반응형 --require main 1440x900 390x900 390x600
```

`SKILL_DIR`는 이 `SKILL.md`가 있는 폴더다. 창을 줄일 때 메뉴가 닫히면, 확인한 버튼의 CSS 선택자를 `--reopen`으로 지정해 다시 연다. 스크립트는 캡처 후 시작 크기를 복원한다.

이 단계의 결과로 **실측값과 원본 스크린샷**을 남긴다. 검증한 화면과 상태를 보고 `가격표-반응형`처럼 검사 이름을 짓는다. 결과는 `.geomjeung/YYYY-MM-DD/<검사-이름>/`에 저장한다. 날짜는 실행 환경의 현지 날짜다. 같은 이름으로 다시 검사하면 `-2`, `-3`을 붙여 이전 결과를 보존한다. 스크립트를 쓰는 경우 각 크기의 결과가 `report.json`에 기록된다.

## 4. 잘리거나 겹친 곳을 표시한다

원본 스크린샷을 크기별로 열어 비교한다. 텍스트나 버튼 일부가 잘렸거나, 다른 요소가 덮었거나, 콘텐츠가 화면 오른쪽으로 밀려난 곳을 찾는다. 웹과 Electron에서 원인을 확인할 때는 같은 화면을 Chrome DevTools MCP로 확인하고 요소 위치나 CSS를 근거로 삼는다.

문제가 보이면 이미지 왼쪽 위부터 센 픽셀 좌표로 표시할 영역의 `x,y,너비,높이`를 정한다. 브라우저의 CSS 픽셀을 쓴 경우에는 스크린샷의 실제 픽셀 크기에 맞춰 변환한다. 예시의 숫자는 문제가 보이는 영역으로 바꾼다. 한 이미지에 여러 곳을 표시하려면 `--box`를 반복한다.

```bash
python3 "$SKILL_DIR/scripts/annotate.py" 02-390x900.png --box 278,92,96,42
```

이 단계의 결과로 **문제에 박스를 그린 이미지**를 남긴다. 스크립트는 원본 PNG 옆에 `02-390x900-marked.svg`를 만든다. 원본 PNG는 그대로 보존한다.

## 5. 결과를 남긴다

결과 폴더에 `findings.md`를 작성한다. 폴더가 없다면 3단계의 경로대로 만든다. 화면, 요청 크기와 실측 크기, 각 크기의 결과를 적는다. 문제가 있으면 어떤 요소가 어떻게 잘렸거나 겹쳤는지 한 줄로 적고, 원본과 표시한 이미지를 함께 링크한다. 깨짐을 찾지 못했다면 확인한 크기와 화면 상태를 적는다. 요청 크기에 도달하지 못했다면 실제로 도달한 크기를 별도로 적고, 요청한 크기는 `미검증`으로 남긴다.

## 6. 관제탑에서 결과를 연다

결과를 기록한 뒤 검사 대상 프로젝트의 루트에서 관제탑을 갱신한다. `RESULT_DIR`에는 이번 검사 폴더의 경로를 지정한다.

```bash
python3 "$SKILL_DIR/scripts/dashboard.py" --run "$RESULT_DIR" --open
```

스크립트는 날짜별 검사 기록을 `.geomjeung/index.html`에 모으고 이번 검사를 기본 브라우저에서 연다. 결과의 캡처와 기록을 참조하므로 HTML 파일은 `.geomjeung` 안에 둔다. 브라우저를 열 수 없으면 사용자에게 HTML 파일 경로를 알려준다.
